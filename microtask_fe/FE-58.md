## Tujuan dan sumber

Tampilkan lifecycle upload dan hasil keamanan secara terpisah. Saat ini `useChunkUpload` tidak mempunyai fase Assembling dan mengubah `INFECTED`/`FAILED` menjadi `done`; `AttachmentPanel` lalu menampilkan “Processed”. Hal ini tidak memenuhi label hasil yang diwajibkan walau daftar attachment yang persisten tetap membatasi download pada CLEAN.

## Target perubahan dan acceptance

- Target: `resources/js/features/attachments/useChunkUpload.ts`, `AttachmentPanel.vue` dan focused tests yang sudah ada (`useChunkUpload.test.ts`, `AttachmentPanel.test.ts`).
- **AC1:** Setelah complete request diterima dan server melaporkan `ASSEMBLING`, tampil “Assembling…” sampai server beralih ke pemindaian/hasil berikutnya. `COMPLETED` dengan security `PENDING` tampil “Scanning for malware…”, belum Ready.
- **AC2:** Hanya explicit `CLEAN` tampil “Ready”. `INFECTED` tampil “Rejected — malware detected”; security `FAILED` tampil “Security scan failed — file not available”. Upload `FAILED`, `EXPIRED`, interruption/resume juga mempunyai pesan berbeda sesuai `07`/`11A`.
- **AC3:** Error/timeout scanner tidak menjadi `done` sukses, tidak memicu refresh sukses palsu, dan tidak menampilkan kontrol download sebelum CLEAN. Server tetap authority atas accepted chunks dan verdict.
- **AC4:** Status berubah secara aksesibel dan aman; progress tidak memberi kesan file telah usable saat perakitan/pemindaian. Tidak menambah business state atau route.
