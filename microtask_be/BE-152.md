# BE-152 — Isian NSCMF opsional dan Forward tanpa gerbang Result

**Phase:** 4 · **Parent resmi:** T22, T24 · **Jenis:** PERUBAHAN KONTRAK (G24)
**Status implementasi:** IMPLEMENTED 2026-09-30 (menunggu human review) · **Hasil pengujian:** PASS lokal (RED `92ff839` → GREEN `573ebc8`; Pest penuh MySQL 8.4; [handoff](../handoff/2026-09-30-optional-fields-date-picker-timeline.md))

## Tujuan dan sumber

Submit/Resubmit hanya mewajibkan Request date. Semua isian lain di Activation dan Change, untuk setiap subtype, boleh kosong. Aturan "wajib bersyarat" dihapus. Forward form Change tidak lagi menunggu Result. Aturan format untuk nilai yang diisi tetap berlaku.

Sumber: [06](../project_doc/06_Validation_Rules.md) §5–9, §21–48, §64–66; [12](../project_doc/12_API_Contract.md) §30, §32; [G24](06_GAP_DAN_KEPUTUSAN.md#g24).

## Acceptance criteria

1. **AC-01:** Submit berhasil untuk setiap subtype dengan hanya Request date terisi.
2. **AC-02:** Blok service, pasangan Plan/KPI, keterangan `Other`, migrasi tanpa domain/hosting, dan baris Result yang terisi sebagian tidak menolak Submit/Resubmit.
3. **AC-03:** Forward form Change tanpa Result berhasil. Detail Review tidak lagi mengirim `forward_readiness`.
4. **AC-04:** Tetap `422 VALIDATION_FAILED` untuk:
   - Request date kosong, atau di masa depan saat first Submit;
   - Target date di masa lalu;
   - format IP/DNS/FQDN/MX/LAN salah;
   - pasangan Monitoring.
5. **AC-05:** Record Approved yang hanya berisi Request date tetap bisa diekspor.
