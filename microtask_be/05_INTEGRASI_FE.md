# Integrasi FE dan baseline konsumen

## Executive finding

The repository contains substantial **isolated Vue/Vitest implementation through FE-30**, but it does not contain the application/backend surface needed to call that implementation integrated. `routes/web.php:8-10` exposes only `GET /`; no login, dashboard, NSCMF, review, administration, setup, temporary-password page, or result-only page route exists. The only Playwright test is the non-mutating Welcome smoke test (`tests/Browser/welcome.spec.ts:3-8`). Therefore FE-01..30 may be described as having implementation/tests at the component boundary, but none can be called live-contract integrated or Feature Done.

The most concrete integration defect is transport-level: approved contract `12` §4.2 explicitly classifies **Draft/Revision autosave and narrow Change Result update as structured JSON endpoints** (`project_doc/12_API_Contract.md:113-126`), while current FE calls both through Inertia `router.patch` and expects Inertia page props/error bags/flash (`resources/js/features/nscmf/useDraftSave.ts:194-310`; `resources/js/Pages/Nscmf/ChangeResults.vue:252-287`). Payload bodies are shaped correctly, but the response/error transport is not. This was not caught because both suites replace `@inertiajs/vue3` with the local double (`useDraftSave.test.ts:4-8`; `ChangeResults.test.ts:6-10`).

Microtask documentation itself currently says all 57 tasks are “PLANNED/belum dieksekusi” (`microtask_fe/README.md:3`), which is stale for FE-01..30. The handoff is closer to reality: FE-01..25 were merged, then FE-26..30 were merged and audited (`e3c2e25`), but its older statements that FE-26..30 are not started are superseded by `handoff/06` and `handoff/07`.

## Concrete HTTP, projection, and composition gaps

1. **All canonical page routes missing.** Contract page routes are `/dashboard`, `/nscmf/create`, `/nscmf/{record}`, `/nscmf/{record}/edit`, `/review`, `/review/{record}`, `/approval`, `/approval/{record}`, `/history` (`12:1057-1069`). Repository route table has only `/` (`routes/web.php:8-10`). Admin, auth and public validator pages are also not mounted.
2. **Draft JSON response undefined in FE and unimplemented in BE.** Request body matches §§27-28, but FE assumes an Inertia page containing `props.record.record_version`. JSON success should use the standard envelope unless `12` is synchronized to declare another shape. FE needs an explicit response DTO (at minimum authoritative new version and any warnings/projection) and `fetch`/Axios-equivalent same-origin JSON transport with CSRF/session semantics.
3. **Change Result JSON response has the same defect.** Exact request allowlist is correct, but success adopts `newPage.props.record`; conflicts/validation use Inertia callbacks. Define authoritative JSON success projection (new `record_version`, normalized results, warnings if any) and standard JSON errors.
4. **No Edit composition.** FE-20..28 components have no `Pages/Nscmf/Edit.vue`; therefore the only end-to-end draft form does not exist. Need GET edit projection preserving exact family DTO and server-derived allowed actions.
5. **Initial setup path/projection.** `Setup.vue` expects readiness flags (`roles_configured`, `teams_configured`, `users_configured`, `setup_completed`, and signing readiness in the component/test), but `12` defines no setup GET path or exact projection. Bind only after contract ownership is settled; reuse normal mutations as intended.
6. **Mandatory password page.** Only POST is canonical (`12:1370-1376`); GET/render path and exact new-password/confirmation keys remain G01/G09. Server middleware must prevent normal navigation until cleared; isolated page absence of links is insufficient.
7. **One-time credential channel and headers.** `12` permits successful response/render but provides JSON examples. Current flash extraction is an unapproved concrete channel. The backend contract must choose an immediate JSON or render channel without server-session flash persistence, guarantee one reveal, set `Cache-Control: no-store`, prevent history/cache replay, and never log response bodies (`12:1414-1479,1503-1545,1755-1767,1983-1985`). FE-52 must inspect the real response and browser back navigation.
8. **Result-only render.** PATCH is specified; dedicated GET page path is not. Decide whether `ChangeResults.vue` is rendered through an allowed action/link on an existing detail route/modal or approve a canonical GET. Do not infer `/nscmf/{record}/change-results/edit`.
9. **List/detail projections.** Dashboard counts/items, Review/Approval/History pages, record detail/edit, audit rows, attachment lists, export states and shared auth props lack exact sanitized TypeScript shapes (G02). FE local types must not become backend authority.
10. **Bulk export.** Endpoints exist, but request IDs/filter selection, batch response, item error shape, limits, and package semantics do not (`12:1283-1290`; G04). FE-46 can only build isolated selection UI before synchronization.
11. **Admin mutation bodies.** Team/user/role exact bodies beyond the explicitly documented fields remain G09; never copy database columns or spread local objects. Settings names are explicitly `automatic_cleanup_enabled`, `retention_value`, `retention_unit` (microtask form contract line 125), not DB names.
12. **Workflow/action actual state.** FE-28/30 render expected behavior, but submit/review/approval/cancel/reopen/archive endpoints, server authorization, audits, state locks and concurrency are absent. Client `allowed_actions` and permissions are hints only (`12:1739-1741`).

## Safe browser disposable boundary

Current `playwright.config.ts:24-29` starts `php artisan serve` without `--env=testing` and therefore reads the ordinary `.env`; `reuseExistingServer:false` does not make the DB disposable. The protective check in `tests/TestCase.php:33-42` only runs inside PHPUnit/Pest application tests; browser traffic never instantiates that test base class. `phpunit.xml:27,33` sets `APP_ENV=testing` and `DB_DATABASE=nscmf_testing` only for PHPUnit. Consequently, mutating Playwright journeys can target the developer DB. This is exactly G08 (`microtask_fe/06_KONTRAK_DAN_GAP.md:56`) and the execution rule at `02_ATURAN_EKSEKUSI_TDD.md:66-83`.

Before any mutating browser test, an explicitly approved test setup task must provide all of:

- a dedicated browser-server environment (`APP_ENV=testing`, explicit MySQL 8.4 database ending `_testing`, dedicated session/cache/queue database state);
- a startup guard executed by the served application/command, not merely Pest, that aborts unless the database identity is explicitly disposable;
- deterministic migrate/seed/factory setup scoped to that DB and per-suite cleanup; never reset local development data;
- synthetic credentials issued within the test environment, no hard-coded production/bootstrap password and no screenshots/traces containing temporary passwords;
- a distinct port/process and health check, with failure artifacts redacted as required by `16:1061-1072`;
- Chromium, retries `0`, and no backend test-only authorization bypass (`playwright.config.ts:5-23`; `16:1042-1059`).

Until then, only non-mutating Welcome/browser smoke is safe. Component tests can continue, but cannot close FE-52..55.

## Recommended documentation correction for the authorized microtask_BE work

The backend backlog document should treat FE-01..30 as existing client consumers and create integration work rather than rebuilding UI. The first backend-facing closure slice should specify:

1. canonical page route/render inventory and exact sanitized props;
2. two explicit JSON contracts for Draft and Change Results, including success envelope/version/results and all negative paths;
3. initial setup and mandatory-password render ownership;
4. one-time credential response mechanism plus `no-store`/no replay tests;
5. result-only render/navigation decision;
6. list projections for Dashboard/Review first, followed by Approval/History;
7. disposable browser environment as a separate explicitly authorized infrastructure/test task before mutating journeys;
8. bulk export kept blocked until its wire/packaging contract is approved.
